Коды для оценки неодназначности и неполноты запроса:
MISSING_TIME — не указан период времени.
Применяется, когда в вопросе нет ни конкретной даты, ни интервала, ни относительного указания на время. Если есть «в 2024 году», «за январь», «сегодня», «за последний месяц» — код не ставится, даже если интервал размытый (для размытых интервалов есть отдельный код VAGUE). Оценка штрафа: 0.35.

MISSING_CRITERION — не указан критерий фильтрации.
Применяется, когда вопрос просит «показать X», но не говорит, каких именно X. Пример: «Покажи клиентов» — всех? Из Москвы? С долгами? Если критерий есть хотя бы частично — код не ставится. Оценка штрафа: 0.25.

MISSING_SORT — не указано поле сортировки.
Применяется, когда вопрос использует слова «топ», «лучшие», «худшие», «первые», но не называет, по какой метрике их определять. «Покажи топ-10 клиентов» — топ по какой сумме? Если метрика названа — код не ставится. Оценка штрафа: 0.20.

MISSING_AGG — не указана агрегация.
Применяется, когда вопрос предполагает агрегацию по группе, но не говорит, какую именно: сумму, среднее, количество, максимум. «Покажи продажи по регионам» — сумма продаж, средний чек или количество заказов? Оценка штрафа: 0.25.

MISSING_LIMIT — не указано ограничение количества.
Применяется, когда вопрос запрашивает «первые», «несколько», «выборку», но не говорит сколько именно. «Покажи первые заказы» — первые сколько? Оценка штрафа: 0.15.

VAGUE — размытое слово без порога.
Применяется, когда в вопросе есть слово-оценка, не имеющее чёткого числового определения. Слова-триггеры: «крупный», «мелкий», «дорогой», «дешёвый», «популярный», «недавний», «старый», «важный», «активный», «успешный», «хороший», «лучший» (если без метрики), «надёжный», «прибыльный», «выгодный». Оценка штрафа: 0.30.

SCOPE — неоднозначный охват сущностей.
Применяется, когда вопрос упоминает несколько объектов через «и» или перечисление, и непонятно: их надо соединить (JOIN) или вывести отдельными списками. «Покажи продажи и клиентов» — это JOIN или два списка? Оценка штрафа: 0.35.

ATTACH — неоднозначная привязка уточнения.
Применяется, когда уточняющая фраза в предложении может относиться к разным частям запроса. «Продажи за месяц по регионам» — «за месяц» относится ко всем продажам или к каждому региону отдельно? Оценка штрафа: 0.30.

UNKNOWN_TABLE — неоднозначное имя таблицы.
Применяется, когда слово в вопросе может соответствовать нескольким таблицам в схеме. «Покажи продажи» при наличии таблиц sales и orders — какую брать? Оценка штрафа: 0.50.

UNKNOWN_COLUMN — неоднозначное имя колонки.
Применяется, когда слово в вопросе соответствует нескольким колонкам. «Отсортируй по дате» при наличии order_date и ship_date — по какой? Оценка штрафа: 0.40.

MISSING_TIME — вычесть 0.35

MISSING_CRITERION — вычесть 0.25

MISSING_SORT — вычесть 0.20

MISSING_AGG — вычесть 0.25

MISSING_LIMIT — вычесть 0.15

UNKNOWN_COLUMN — вычесть 0.40

Правило приоритета:

Если кодов нет → clear.

Если среди кодов есть хотя бы один из группы смысловой неоднозначности (VAGUE, SCOPE, ATTACH, UNKNOWN_TABLE, UNKNOWN_COLUMN) → ambiguous.

Иначе, если есть только коды группы нехватки данных (MISSING_TIME, MISSING_CRITERION, MISSING_SORT, MISSING_AGG, MISSING_LIMIT) → incomplete.

Логика такая: ambiguous — более сильная проблема. Если вопрос можно понять по-разному, это важнее, чем отсутствие какого-то поля. Поэтому ambiguous имеет приоритет.
